# Reference Catalog Provenance

The JSON files in this directory contain identity fields used to validate
foreground links: activity or flow names, reference products, locations,
categories, and units. Schema-version 2 resources also contain the exact
ecoSpold2 activity, intermediate-flow, and elementary-flow UUIDs from the
named release and system model. They do not contain exchange amounts or
complete background inventories.

The ecoinvent catalogs were generated by
`scripts/generate_reference_catalogs.py` from locally installed, licensed
ecoinvent releases. The UVEK 2025 technosphere catalog was generated from a
locally supplied Brightway-compatible workbook; its biosphere identities came
from the ecoinvent 3.10 biosphere database.

`RESOURCE_MANIFEST.json` records exact SHA-256 hashes, sizes, profiles, and
identity counts. Its `legal_review_required` status is intentional: maintainers
must confirm that distribution of these derived identity catalogs is permitted
under the applicable source-data agreements before a stable public release.
The manifest is an integrity and provenance record, not a license grant.

The patch catalogs are generated by `scripts/build_patch_catalogs.py`.
The 3.9.1 cut-off catalog uses the locally installed exact 3.9.1 release.
The original 3.10.1 technosphere identity list reused 3.10 based on ecoinvent's
explicit statement that 3.10.1 contains the same datasets:
https://support.ecoinvent.org/ecoinvent-version-3.10.1 . UUID enrichment was
then performed against the downloaded exact 3.10.1 cut-off ecoSpold2 release;
all 23,523 technosphere and 4,362 biosphere identities matched. This is evidence
for link identity compatibility only, not equality of background coefficients,
uncertainties, or impact scores.
The 3.9.1 release explicitly removes some suppliers; the exact catalog is used:
https://support.ecoinvent.org/ecoinvent-version-3.9.1 .

UUID-bearing catalogs are enriched from extracted exact ecoSpold2 releases by
`scripts/enrich_reference_catalog_uuids.py`. UUIDs are never inferred from an
adjacent version or system model. The manifest records UUID coverage separately
from identity coverage; a zero or partial count means callers must supply an
explicit exact ecoSpold2 reference catalog for that profile.
